## 本轮补齐的能力

| 功能 | 交付行为 |
|---|---|
| 正常后台生命周期 | 隐藏、独立的监护进程启动后台；启动命令退出后仍运行。检查实例和端口归属，拒绝同目录双写；有认证的 stop/status，异常退出后可显式重启，不做无限重启循环。 |
| 安全默认值 | 凭证保护在候选构建中固定启用，不依赖实验开关；移除 lab 控制接口。保留原生认证与 CSRF，加管理入口允许列表及本地 Host/Origin 检查；普通凭证 JSON 导出与 reveal 不开放。 |
| 正常管理 | 原生 API 管理账号、凭证、客户端 key、账号范围、combo 与 per-provider 轮转。客户端 key 明文只在显式取用时返回，管理结果脱敏；API key 使用 Windows Credential Manager，SQLite 存引用。 |
| 迁移工具 | 只读事务预览旧 SQLite，检查来源指纹、完整成员、已知策略。凭证经私有 stdin 明确输入，不扫描正式 vault；全部映射齐备后才建新实例，重发客户端 key，输出无密钥迁移报告。未支持格式明确阻塞。 |
| 节流配置 | 随包工具应用并读回原生保守配置：每账号至少 20 秒、并发 1、每分钟 3 次；继续使用既有 dispatch floor 修复和有界原生等待。 |
| 备份恢复 | 停止实例并 checkpoint 后，以 AES-256-GCM+scrypt 加密 DB、匹配 vault、启动秘密及当前配置；错误口令/篡改在写新目标前拒绝。restore/rollback 只到新目录，匹配精确发行版本，不覆盖原实例。 |
| WorkBuddy | 随包窄连接器与既有首行函数；移除 16 次实验寿命预算，保留失败冷却与有界请求。官方当前凭证只读、账号绑定，不刷新或复制明文会话；协议转换仍交给 OmniRoute。 |

“凭证不落盘”在这里指不进入普通数据库、日志和请求记录；允许 OS 保护的凭据库及用户显式加密备份。Node 字符串不承诺 Rust 式内存清零；同权限恶意进程不属于此隔离工具的安全边界。

本地完整 HTTP mock 基准 20 次：p50 **76.48 ms**、p95 **81.10 ms**。429 后同账号的真实墙钟间隔约 20 秒；25 秒 Retry-After 用例为 25,121 ms，排除的健康账号未被越界使用。这些结果验证等待与节流行为，不是模型性能，也不证明商汤真实风控解除。

### 保留失败及其处理

1. 初轮测试误用 `PUT /api/keys/:id`，修正为原生 `PATCH`；没有为测试改接口。
2. 初版管理允许有效 session、有效 CSRF 加外站 Origin。这不等于匿名鉴权绕过，但未达到本包的本地管理要求。仅在已有 proxy 接缝补 Host/Origin 检查，重新构建并归档后重跑全部组。
3. WorkBuddy 工具 schema 被原生转换补充空 `properties` 和 `additionalProperties:true`。原描述、参数和其余正文未被改写；断言改为明确的原生补全结果，不扩大首行或协议补丁。
4. 最终包 Host 用例最初仍失败，loopback 回显确认 Node `fetch` 将自定义 Host 改为 URL authority。测试改用原始 HTTP 后，8 项 management 检查全部通过。发行包未改，仅重跑该组；另外 7 组保留同一最终包的通过回执，审计记录原始运行和定向重跑来源。

相关失败回执仍保留于 evidence，未以新结果覆盖或将旧包成绩混入最终包。

## 维护范围和采用判断

接缝清单显示：相对固定上游，17 个运行时文件共 +128/-19 行；比上一阶段增加 2 个文件，分别是安全 settings 默认值和 proxy 管理入口。另有构建用 tsconfig 变更、自有适配模块、可发布工具和生成 server.js 的隔离启动守卫。这个行数只描述上游文件差异，**不包含全部自有工具维护量**。

本轮没有新增路由器、改 SQLite schema、扩充 Provider 协议栈或扩大 WorkBuddy 提示词替换。独立工具解决了分散实验脚本与开发路径依赖，范围仍可控制，因此值得继续融合。它仍是需要维护的 fork，不是零维护插件。实际构建复用了已下载依赖和工具链，跳过上游全局 typecheck；不能据此声称洁净联网重装或上游全部测试通过。仓库许可证检查通过，也不等于整个 Node 依赖树的独立法律审计。

## 剩余事项分开验收

| 类别 | 剩余事项及边界 |
|---|---|
| 网关迁移 | 实际旧 `gpt` 池中 `codex-sub/account-1`、`commandcode/account-1`、`opencode-go/account-1` 的绑定仍需明确。此次只验合成源；未知子号池格式、订阅接入和不支持的端点策略仍明确 BLOCKED，未静默丢成员。工具具备受支持映射流程，不代表实际配置已无损迁移。 |
| 网关升级 | 下一固定上游版本须重放**包括本轮全部增量**的升级、回归及回滚。历史 v51→v52 不覆盖全部新改动；本轮 backup/restore 是精确发行版本配套恢复，不能用于任意跨版本恢复。 |
| 商汤外部状态 | 历史真实 429；用户已确认额度正常，按风控处理。包内节流通过，但本轮未重新调用，等待合适时机进行少量固定账号/模型验收。 |
| CommandCode 外部状态 | 历史 401/EXPIRED，用户处理后再做有限验收；本轮不继续排查账号。 |
| WorkBuddy 外部状态 | 依赖官方桌面登录和绑定账号；本轮合成轮换通过，真实自然轮换仍未观察，不强制登出或刷新制造事件。 |
| 客户端测试环境 | 既有文件工具 `blocked by policy` 继续独立保留；不修改网关或客户端权限，不扩大调试范围。 |

迁移过程普通失败会清理新凭据并保留失败目录，但不承诺中途断电自动回滚。WorkBuddy 仍限制请求 256 KiB、响应 1 MiB、65 秒、2048 输出 token、单并发，并完整缓冲 SSE；不能宣称实时 token 流或无限长会话。

本轮交付完成的是隔离便携后台与必要工具，没有 UI、安装/自启、正式账号迁入或生产切换。下一步聚焦实际映射和完整组合的升级成本；外部账号与客户端环境保持各自验收状态。
