# 融合网关可用性盘点与最小交付范围

日期：2026-10-30。基于 ExecPlan 042–049 的现有代码与回执整理；本轮只读核对并编写本文，没有启动客户端、后台或真实 Provider 调用，没有修改正式环境或 UI。

**2026-10-31 实施更新：** [050 统一隔离包](2026-10-31-isolated-fusion-package.md)已完成独立发行、正常管理、安全默认值、受支持迁移/备份恢复工具及同一最终包 120/120 检查。以下保留实施前清单；“尚未形成统一包”与实验接口耦合已被本次交付解决。第 3 项的实际旧池成员绑定仍未完成，第 5 项包含全部最新增量的下一版本升级仍待验收；外部账号和客户端环境状态不变，不批准正式切换。

## 结论与可用性的定义

**继续 OmniRoute 窄融合更合适，不退回全量自研。当前已经验证主要技术路线，但尚未形成包含全部最新适配、能脱离实验目录独立运行的统一交付包。下一步应收拢交付，不继续扩展客户端调试。**

区分两个目标：

- **可交付的隔离试用包**：固定底座、自带必要运行依赖，有正常启动、配置、停止、迁移、备份与恢复入口；同一个最终包通过网关回归。真实 Provider 不可用时明确报错，仍能验收包本身。
- **可替代现有日常用途的融合版本**：在上述基础上，保留的旧池完成映射，商汤、CommandCode、WorkBuddy 三类真实用途验收通过，并具备包含当前全部增量的跨版本升级与回滚证据。当前尚未达到，不批准正式切换。

两者都无需 UI。正式切换仍需另行安排，不能由隔离验证自动转成部署。

## 必要工作：围绕同一个交付包收口

| 顺序 | 必要工作 | 最小范围与完成标准 |
|---|---|---|
| 1 | 统一独立运行包 | 将固定后台、现有 WorkBuddy 连接器、首行适配、必要 Node/原生绑定、迁移工具及许可证收进同一版本清单。消除对开发 checkout、实验目录及固定 `C:/Python313/python.exe` 的运行依赖；可携带必需运行时或声明可检查的安装前提，不另造工具框架。换到一个新的隔离目录仍可运行。 |
| 2 | 正常安全入口与生命周期 | 将安全保护从实验开关中分离，发行包不暴露实验控制接口；通过已有鉴权管理 API 加薄脚本完成账号、凭证、客户端 key 与路由配置。提供 start/stop/status，检查端口、数据目录和凭据空间归属，避免同目录双写；关闭启动终端不应带走后台。正常退出/异常重启后仍保持安全设置，缺失凭证明确拒绝。 |
| 3 | 完整迁移、备份与回滚流程 | 复用现有预览/编译/加密备份工具，补齐实际保留的旧池成员绑定、主/子号池选择及新别名映射；不能静默省略成员。迁移报告说明新地址、新 key 和不支持的项。匹配包版本、DB、vault、配置；停止旧实例后切换，用升级前副本回滚，避免直接用旧程序打开已升级数据库。WorkBuddy 备份连接/账号绑定配置，不复制官方会话明文。 |
| 4 | 最终交付包的集中回归 | 对同一个打包产物复用既有用例：凭证增改删/撤销/导出恢复及明文检查；三协议账号范围、模型不变、等待/重试上限、429 节流、取消与已输出后不重放；WorkBuddy 首行范围、会话读取及账号变化拒绝；迁移/恢复/回滚。主要使用 HTTP mock，不依赖某个客户端的本机命令执行权限。运行时改动涉及网关时保留有针对性的 benchmark。 |
| 5 | 当前全部增量的升级成本验收 | 对选定的后续固定上游版本，验证包含凭证/路由接缝、429 补丁及连接器依赖的完整组合，记录实际冲突、修改范围、构建和回归结果，并实走恢复/回滚。已有相邻版本升级是基础证据，不覆盖之后新增的全部适配；静态 patch 可应用也不能代替实际升级。无需追每个上游发布。 |

第 1–4 项形成隔离试用交付物；第 5 项在决定长期采用和正式替代前完成。处理依赖边界时允许顺序交叉，但不在中间阶段引入 UI 或正式流量。

### 两个必须显式处理的实验遗留

**安全开关和实验控制接口耦合。** 当前 `src/lib/loadoutPhase1/secretStore.ts` 通过 `LOADOUT_PHASE1=1` 启用保护，`src/app/api/loadout-lab/route.ts` 也由该开关与实验控制密钥保护。不能简单关闭开关来移除实验入口，否则可能同时关闭保护。当前接口有实验鉴权，不应误报为无鉴权；发行准备需要把安全 profile 和测试控制面拆开，并验证正常管理入口。后台安全默认值也不能只靠测试 harness 运行后注入。

**WorkBuddy relay 仍带实验运行约束。** 当前默认总调用预算 16、每场景预算、失败停止状态适合受控实验，不适合作为常驻服务的寿命限制；还存在 256 KiB 请求上限、1 MiB 响应上限、65 秒超时、2048 输出 token 上限和上游 SSE 完整缓冲。打包前必须明确哪些是测试预算、哪些是产品可配置上限，移出测试总预算，保留有界失败处理。不能把缓冲转发宣称为实时流式，也不能把 200 KiB 级长会话成功宣称为无限上下文。优先复用现有能力；若这些限制妨碍明确的日常需求，再单列最小差距，不为此预先扩写协议栈或路由。

## 迁移清单里的未决项

旧 `gpt` 池的历史预览仍有 `codex-sub/account-1`、`commandcode/account-1`、`opencode-go/account-1` 成员绑定未完成。这是源配置到新网关的映射问题，和“Codex 客户端能否执行 PowerShell”是两回事。

后续制作交付包时，应对实际源配置做一次只读预览，明确每个成员是绑定已有受支持接入、等待外部恢复，还是经用户明确决定退役。不能自动删除成员后声称无损迁移，也不因为一个旧成员未绑定就自动新增订阅凭证推理 Transport。旧预览中严格等待策略的阻塞已被接受原生等待的决定取代，不再作为当前缺口。

## 为少维护而明确不做

- 不恢复 RouteSnapshot、零 SQL、旧端点严格 30 秒期限；不重写路由或做双实例共享 SQLite。
- 不保留全部旧 URL/CLI/界面形式；通过迁移报告交代新地址、别名和 key。
- 不做 Magpie UI、token 流向可视化、免费资源池发现/更新时间界面；这些不阻塞第一版后台交付。
- 不扩到全部 OAuth/订阅/网页会话 Transport，不扩大 WorkBuddy 首行替换；有状态 Responses 保持已有明确拒绝边界。
- 不新增自研自动更新框架、桌面壳、动态账号同步或客户端调试平台。
- 开发参考 checkout 和实验脚手架暂时保留；发行包不依赖它们，完成融合后再按既定安排清理。

目前后台改动已从 042 的 14 个上游接缝增加到节流候选的 15 个；042 的实际跨版本移植出现过 8 处内容冲突及已存在文件的问题。因此应称为**有限改动的受控 fork**，不能称零维护插件。若整理独立包需要继续大面积改上游，或升级验证暴露持续扩散的接缝，再重新评估该部分是否值得保留；不要提前以旧实现约束否定已验证的原生 SQLite 路线。

下一次实施应只围绕“统一隔离后台包 + 最小管理/迁移工具 + 同包回归”建执行计划，并按真实新增行为更新 ADR-019 与验收边界。本次盘点不启动该实施，不构成切换正式环境的授权。
