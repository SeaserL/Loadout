# 071 — 1.1：全量版与 lite 版

## Goal
用户决定不发 1.0.1，直接发 1.1，分两个版本：

- **lite**：保留核心功能，体积明显更小，性能和内存开销小。
- **全量**：功能齐全，中文必须可用。

1.1 同时纳入 2026-11-06 讨论定下的功能（见 Scope）。1.0.0 的发布包没有更新器（ADR-020 Consequences），已经装了 1.0.0 的用户要手动下载一次 1.1，之后可以用内置更新。

## Context
2026-11-06 用 067.1 候选包、隔离实例和 mock 上游测得：

- **体积**：发布 ZIP 561 MiB，解压后 1.63 GiB。可去掉的部分：
  - `docs/`（中文以外的 i18n 占了 607 MB 解压体积），只有 `docs/api/search` 读它；
  - OmniRoute 原版后台的 67 种界面语言，ZIP 中 23.5 MB；Loadout 控制台只调用 `/api/auth/csrf` 和 `/api/loadout/rpc`；
  - OmniGlyph 和 gpt-tokenizer，19.2 MB；
  - sql.js，10.1 MB，数据库实际用 `node:sqlite`；
  - 打进包的构建工具（esbuild、tsx、babel 编译器、@types），6.7 MB；
  - playwright-core，3.6 MB；
  - 文档搜索接口和赞助商图片，3.7 MB。
  
  另外 `archive.py` 用 deflate 级别 1，改成 9 对同一组文件少 14%。
- **内存**：用户机器上 Loadout 共约 684 MB 工作集。
  - 控制台 WebView2 约 385 MB。关闭窗口只是隐藏（`apps/fusion-desktop/src/main.rs` 的 `CloseRequested`），内核一直在内存里。
  - 后端刚启动空闲时约 320 MB 私有内存，300 个请求后约 400 MB。
  - 守护进程约 60 MB。
- **限速**：OmniRoute 给每个 API key 账号默认开请求队列：60 rpm、两次请求间隔至少 350 ms、并发 6，排队超过 30 s 报 503 换号。
  - Loadout 从没改过这个默认值。ADR-019 的 042 记录里就写过“350ms 主要来自默认主动限速”。
  - 实测 10 个并行请求按 350 ms 间隔串行放行。连续 60 个之后，第 61 个先等 30 s，503 后才换号。
  - 用户实例的 `call_logs` 里有约 10 次这类 503。
- **单请求开销**：后端单个请求约 100 ms，其中 CPU 34 ms。ExecPlan 050 的记录是 p50 76 ms。
- **中文**：
  - Caveman 中文规则 16 条，英文 49 条。`zh_filler_please` 不看词边界，会把“请求”“申请”中的“请”删掉。
  - session dedup 的模糊匹配按空格切 shingle，中文句子永远匹配不上。
  - 记忆的 FTS5 用默认分词器，不会切中文。
  - 注入防护没有中文说法，PII 规则没有中国手机号、身份证、银行卡。
  - LLMLingua-2 小模型（tinybert、mobilebert）是英文词表。
- **ADR-008**：用户实例开着 `semanticCacheEnabled`，`semantic_cache` 表存了 18 条响应正文，违反“请求正文默认不落盘”。
- **模型来源**（子任务核实，2026-11-06）：

  | 模型 | int8 大小 | 许可证 | 中文 | ModelScope |
  |---|---|---|---|---|
  | bge-small-zh-v1.5 | 23.9 MB | MIT | 是 | 有 |
  | multilingual-e5-small | 118 MB | MIT | 是 | 有 |
  | bge-m3 | 569 MB | MIT | 是 | 有 |
  | LLMLingua-2 mBERT（atjsh JS 版） | 178 MB | Apache-2.0 | 是 | 没有 |
  | PP-OCRv5 mobile（RapidOCR） | 22.5 MB | Apache-2.0 | 是 | 有 |

  - LLMLingua-2 论文附录 J：LongBench 中文、5 倍压缩下得分 38.1，不压缩 42.5。
  - ModelScope 的文件地址是 `/models/{id}/resolve/master/{file}`。
  - transformers.js 设置 `remoteHost` 和 `remotePathTemplate` 后能从 ModelScope 下载。
  - 硅基流动的 bge-m3 向量接口免费；百炼 text-embedding-v4 收费 0.5 元 / 百万 token。

## Existing behavior
- 一个发布包。资产名是 `Loadout-<版本>-portable-windows-x64.zip`，更新器只认这个名字。
- 以下设置被 `distribution.ts` 的 `fusionSafety` 固定，用户改不了：`credentialRedactionEnabled: true`、`promptCacheAffinityEnabled: false`、`disableSessionStickiness: true`、`mcpEnabled: false`、`a2aEnabled: false`。
- 控制台“设置”页的条目来自 `control/system.ts` 的 `DEFS`。
- 压缩、记忆、PII、注入防护、MCP、客户端配置写入都没有 Loadout 入口（`fusion-backend-status.md` 的“暂不纳入”）。

## Scope
开关（括号内是默认值）：

1. 响应缓存（关）。打开时说明会在本机保存回复正文；升级时清空现有条目。
2. 密钥脱敏（开）。
3. 个人信息脱敏（关）。补中国手机号、身份证（带校验位）、银行卡（Luhn）。
4. 注入防护（关）。补中文说法。
5. 提示词压缩：特色开关，可以按号池或客户端设置。
   - 两个版本都有 RTK、去重、Caveman。
   - 全量版另有 LLMLingua-2 多语言版。
6. 记忆（关）。
   - 关键词检索先用中文分词处理。
   - 向量检索二选一：服务商的向量接口，或全量版里的本地 bge-small-zh。
7. 模态桥（关）。两种模式：本地 OCR（全量版，PP-OCRv5），或调用看图模型生成描述。
8. 缓存亲和：开关，默认值实测后再定。

功能：

9. 号池策略分成“基础”和“高级”两级。
10. 自动模型档位：最快、最便宜、最强、编程。
11. MCP。
    - 精选的只读工具默认开；操作类工具另设开关。
    - 按客户端 key 限制能看到的号池。
12. 一键写入客户端配置。

核心修复：

13. 默认关闭 API key 账号的请求队列，靠上游的 429 和 failover；需要限速的账号单独设置。
14. 查清后端单请求开销，并把基准测试加进发布流程。
15. 控制台窗口关闭时释放 WebView，从托盘打开时重建。
16. 后端内存：关闭的功能不加载；去掉启动时就加载的无用模块。目标是空闲 200 MB 以内，以实测为准。
17. 中文修复：
    - Caveman“请”的词边界；
    - 去重模糊匹配按中文分词；
    - FTS 分词（`Intl.Segmenter`）。

打包：

18. 两个版本都去掉 Context 里列出的无用内容，ZIP 改用 deflate 级别 9。
19. 版本与 AI 组件包：
    - lite = 本体。
    - 全量 = 本体 + AI 组件包（运行库 onnxruntime-node 只带 win32-x64，加上模型）。
    - 组件包另作一个 Release 资产。更新时组件包版本没变就沿用本机已有的，不重新下载；lite 用户可以在设置里补装。
    - 下载地址只有我们的 Release，不在运行时访问 Hugging Face。ModelScope 作为有同款文件的模型的备用源。

不做：quota share、A2A、云端 agent、sandbox、batch、tunnels、MITM、媒体生成接口、把中文翻成英文再处理。OmniGlyph 只放进全量版，默认关。

## Constraints
- ADR-008：响应缓存和记忆会保存正文，所以必须默认关闭、由用户显式打开、界面写明保存了什么，并修订 ADR-008。其余功能不落盘正文。
- 密钥不进 SQLite、日志、fixture 或错误信息。
- 默认测试不调用真实 Provider。测试不启动 `Loadout.exe`，不写真实 Run 键，不碰用户的实例。
- 不中断 `scripts/fusion/build.mjs`，构建期间不改工作副本。
- 仓库是公开的：fixture 和截图只用合成数据。
- 版本号 1.1.0。上游 OmniRoute 仍是 v3.8.52，不换。
- 推送和发布由用户确认。

## Architecture impact
- **ADR-020 修订**：两个版本的资产名、AI 组件包资产、更新时沿用组件包、`fusion-manifest.json` 标明版本类型和需要的组件包版本。
- **ADR-008 修订**：响应缓存和记忆是用户显式打开的例外，默认关闭，可以清空。
- **ADR-019**：补 1.1 的记录。
- **`fusionSafety`**：去掉要做成开关的几项。首次运行和升级时写入 Loadout 的默认值，用户改过的值不覆盖。
- **包校验**：`verifyPackage` 允许组件包清单里列出的文件，组件包按它自己的清单逐个文件核对哈希。

## Tests
- 限速：并行 10 个请求不再按 350 ms 串行；连续 70 个请求不出现排队 503；单账号手动设置的限速仍然生效。
- 响应缓存：默认关；开关打开后命中；升级后旧条目清空；关闭后不再写入。
- 中文：
  - “这个请求失败了”经过 Caveman 后保持原样，“请帮我看看”去掉“请”；
  - 两段只差几个字的中文段落能被去重模糊匹配；
  - 中文记忆按词能搜到；
  - 手机号、身份证、银行卡被替换；
  - “忽略之前的所有指令”被注入防护识别。
- MCP：每个工具都在允许名单里；没有权限的客户端 key 看不到别的号池；操作类工具关闭时调用会被拒绝。
- 客户端配置：只写测试目录；原文件有备份；重复写入结果不变。
- 包：lite 不含 onnxruntime 和模型；全量的组件包清单校验通过；任何一个文件被篡改都拒绝。
- 更新端到端：用本地的假 Release，覆盖以上四种路径。
- 桌面：`cargo test` 覆盖窗口重建的状态机；真实窗口不在测试中启动。

## Performance validation
- 用 `latency-probe` 的方法测改动前后的单请求开销和并行请求的排队情况。基准测试进入 `run-suite`。
- 用 `mem-probe` 的方法测空闲内存和 300 个请求后的内存，lite 和全量分别测。
- 记录两个版本的 ZIP 大小。

## Security considerations
- MCP 走客户端 key 鉴权并限制范围。操作类工具默认关；任何工具都不能返回密钥。
- 客户端配置写入只改已知文件里 Loadout 相关的字段，写之前备份；客户端 key 不进日志。
- AI 组件包和全量版按清单逐个文件核对 SHA-256。运行时不访问 Hugging Face，transformers.js 设成只读本地模型。
- 个人信息脱敏和注入防护在发送上游前在内存中完成，不落盘。

## Migration considerations
- 1.0.0 → 1.1：手动下载。数据目录和上游版本都不变，原生 migration 无新增。
- 升级时：清空 `semantic_cache`；`semanticCacheEnabled` 改为关；原来被固定的设置（脱敏开、亲和关）写为默认值；号池和账号不动。
- 067.1 → 1.1 的同底座升级和回滚要放进升级测试的允许名单。

## Known risks
- `@atjsh/llmlingua-2` 3.0.0 需要 transformers ^4.2.0，上游锁的版本可能更低，多语言模型能不能直接换上要先验证。
- 中文压缩的质量要实测，效果不理想就在界面标注。
- 后端内存能降多少取决于 Next 的加载方式，200 MB 是目标，不是承诺。
- 组件包沿用让更新流程更复杂，失败时必须能回滚到旧文件夹，组件包也要一起回滚。

## Definition of done
- 两个版本的 ZIP 都通过全量回归、审计和更新端到端测试。
- lite 大小在 120 MB 以内，内存和单请求开销的前后数字记录在 Verification。
- 中文测试全部通过。
- 用户验收。

## Decisions
- 不发 1.0.1：用户希望一次做完，朋友手动下载一次 1.1。
- 模型放在自己的 Release 里，不依赖 Hugging Face：能下载 Loadout 的人就能下载组件包；ModelScope 作为部分模型的备用源。
- 不走“翻成英文再压缩”：翻译本身要调用一次模型，对国产模型也不省 token，还会损失信息。
- 记忆的向量检索优先用服务商接口（bge-m3 免费）。本地模型选 bge-small-zh（24 MB），不选 multilingual-e5-small（118 MB）或 bge-m3（569 MB）。
