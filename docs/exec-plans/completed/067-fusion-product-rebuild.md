# 067 — Fusion 产品化重做

## Goal
用户否定 066 的界面、登录密码和功能取舍。交付一个可双击启动的编译版：不再要求输入密码；保留 Loadout 原版功能（号池、账号拖动排序、模型分组、一键导出 API、总 API、比价、虚拟模型/Pool、客户端策略、统计、日志）；后端以 OmniRoute 为运行时并接入其特色能力（免费目录、价格同步、预算、策略、路由诊断）；前端采用 Magpie 设计语言。根目录放快捷方式。

## Context
066 只保留了内核和设置，账号/路由多为只读。用户明确：功能完好优先，再求好看顺手，用结构设计形成引导；Magpie 风格放不下时可少量用 OmniRoute 的做法。交付前必须由代理自己经 `127.0.0.1` 发出真实请求并跑通，起点是 WorkBuddy（用户授权真实调用，后台已启动，参考 AidenOrz/dsh-workbuddy-connect）。

## Existing behavior
原版 UI 在 `apps/desktop/src`，经 Tauri IPC 调 loadoutd。Fusion 后台是 OmniRoute v3.8.52 + `src/lib/loadoutPhase1`，管理靠 cookie/CSRF，桌面壳在 `apps/desktop/src-tauri` 下与正式 crate 混编，导致标准 `cargo test --workspace` 失败。WorkBuddy relay 固定单模型、2048 token、256KiB、单并发、缓冲 SSE，这些实验期上限不适合日常使用。

## Constraints
不动正式安装、8317、正式数据与凭据；`apps/desktop` 的正式 UI 不改。secret 只进 OS vault，不进 SQLite、日志、前端。client key 继续必需（`/v1` 不免密）。自动探测继续关闭：只有用户点击或客户端请求才访问上游。不提交、不推送。默认别名、订阅转发、GPT 池保持用户此前的停用选择，但在界面上可由用户开启。

## Architecture impact
- 前端复用原版页面，把 `invoke` 换成 `POST /api/loadout/rpc`，方法名与 IPC 一致；新增的 OmniRoute 能力另开板块。
- 后端新增 `src/lib/loadoutPhase1/control/`：Loadout 控制面，读走 SQLite，写走原生 REST（复用校验与 vault 边界），个人状态存原生 `key_value`（namespace `loadout`），不改 schema。
- 号池、总 API 进入同一条选路链：`policy.ts` 只收窄账号范围，不新增 Router。
- 免密：管理 API 仍要会话。Tauri 壳启动时由本机 helper 从 OS vault 取机器凭据换会话 cookie，以 HttpOnly 写入 WebView；用户看不到密码，界面没有登录页。其他本机用户和网页仍进不来。
- 桌面壳独立成 `apps/fusion-desktop` crate，用自己的 `tauri.conf.json`，不再需要 `TAURI_CONFIG`，修复 `cargo test --workspace`。
- 网络：应用实例用 `network: direct`（ADR-019 记录），隔离守卫保留给测试实例。首次出现的外连主机写入本地日志，便于核对“空闲时不连接”。

## Files expected to change
`apps/fusion-console/`、`apps/fusion-desktop/`（新）、`apps/desktop/src-tauri/Cargo.toml`（移除 fusion bin）、OmniRoute 工作副本 `src/lib/loadoutPhase1/`、`src/app/api/loadout/`、`src/proxy.ts`、`fusion/`、`scripts/fusion/`、`tests/fusion/`、`.gitignore`、ADR-019、架构与操作文档。

## Implementation stages
1. 控制面 RPC：账号、模型、Pool、客户端、统计、用量、号池、总 API、比价、导出导入。
2. 请求链接入：号池、总 API、`slug/alias/model` 寻址；WorkBuddy relay 放开实验期上限。
3. 免密与独立桌面壳。
4. 前端：原版功能 + Magpie 语言 + 丝带流向 + OmniRoute 资源页。
5. 整理目录与 .gitignore，修正过期文档。
6. 构建、回归、迁移 059 隔离数据到新实例，代理自己经 127.0.0.1 跑通真实 WorkBuddy，放快捷方式。

## Tests
沿用集中回归；新增 `control-test.mjs`（mock 上游，覆盖 RPC 全链路、号池越权、总 API、导出/导入回环、免密会话）。`cargo test --workspace` 须恢复通过。真实链路只用 WorkBuddy，少量短请求。

## Performance validation
不改 OmniRoute 选路算法。`prepareRequest` 只增加内存读取与一次 KV 读取（缓存），用既有回归里的 mock benchmark 观察。

## Security considerations
RPC 只接受管理会话，拒绝 `Authorization` 头，沿用 Host/Origin/CSRF。导出沿用 `loadout-keys` 信封（PBKDF2 + ChaCha20-Poly1305），口令至少 8 位，两步确认。helper 只经私有管道把 cookie 交给壳，不写文件、不进命令行。

## Migration considerations
新实例由 059 隔离实例经加密 backup/upgrade 复制而来，059 原样保留。不读取正式 Loadout 数据库的凭据。同一 OmniRoute 底座内实例基线放宽为按上游版本判断，避免每次重打包都要迁移。

## Known risks
原版部分能力在新底座上是近似实现：虚拟模型的档位由测速结果生成固定顺序，不是原版的内存快照；用量读取只覆盖 OmniRoute 支持的 Provider。网页会话（ChatGPT Web）未移植。WorkBuddy 上游渠道校验可能再变。

## Definition of done
双击根目录快捷方式打开编译版，无密码；原版功能可用；代理已经经 127.0.0.1 跑通真实 WorkBuddy 请求并记录结果；集中回归与 `cargo test --workspace` 通过。

## 第一轮验收反馈（2026-11-02）

用户意见：顶部导航文字不居中，且和窗口标题栏叠在一起；页内说明文字太多，违背用结构引导的初衷；流向图要接真实请求，有上游流向下游的动效；OmniRoute 的功能没用过，需要使用说明。

改动：

- 导航移到左侧。账号、模型、路由、客户端穿在一条线上，表示一个请求经过的路径；选中项并入页面。窗口宽度小于 1040px 时折叠成图标列。
- 卡片套卡片改成一张平整的页面。状态从药丸标签改成圆点加文字，标识符不再用等宽字体，只有要复制进配置的地址和密钥才用。
- 页内说明文字和横幅移入使用说明，每页标题旁的问号直达对应章节。对话框只保留关乎当下决定的提示（如密钥只显示一次）。
- 流向图改成左上游、右下游。新增 RPC `stats.live`（内存里的进行中请求 + `call_logs` 游标），后端在 `chatCore` 记下客户端名，在 `streamingTail` 统计实际传给客户端的字节数；光点密度跟实际字节速度走。没有请求时图静止，动画循环也停。
- 总览去掉“开始使用”清单：图两端还空着时，“添加账号”和“新建客户端”就显示在图上。
- “资源”页拆掉：免费模型和价格表进模型页，重试与冷却进路由页，预算并入客户端策略。
- 新增使用说明页 `pages/Help.tsx`，只有中文。

走查时查出并修掉的问题：

- “失败前先等待”开关一直没有作用：`fusionSafety` 把直接请求的 `requestRetry` 钉成 0，保存提示成功、实际不变。开关改为控制能生效的分组等待 `comboCooldownWait`，直接请求不等待写进使用说明。
- 旧“预算”页的周、月上限不生效：原生预算只按 `resetInterval` 选一个窗口。现在日、周走密钥上限，月走预算窗口（`resetInterval: monthly`）。
- 旧文案“每日 UTC 00:00 重置”“保留 400 天”不符合这个后端。实际每日上限按 UTC-3 的零点（北京时间 11:00）重置，周为滚动 7 天。错误文案已删；日志保留天数没有核实，使用说明不写。
- 账号卡片隐藏的工具按钮占一行空白，改为悬停时浮在标题上。

## 第二轮验收反馈（2026-11-03）

用户问为什么总有 OpenAI 和 Anthropic 两个地址。实测两类软件填哪个都能通，差别只是 SDK 拼路径的习惯，于是合并成一个：界面只显示 `http://127.0.0.1:8318/v1`。

- OpenAI SDK 在这个地址后接 `/chat/completions`；Anthropic SDK 接 `/v1/messages`，路径变成 `/v1/v1/messages`，上游已有的改写规则会接住。
- 新增三条改写：`/v1/v1/models`、`/e/:name/v1/v1/models`、`/e/:name/v1/v1/:path*`。之前前一条拿到的是原生模型列表，后两条会 404。
- 不带 `/v1` 的旧地址继续可用，已经配好的软件不用改。
- 端点信息去掉 `anthropic_base_url`。

客户端策略的“允许的模型”原来是手填文本，能存下不存在的名字，存了之后客户端只会被拒绝，看不出原因。改成：

- 输入框加提示：边输入边筛选，分组排最前，Tab、回车或点击加入，退格删最后一个。只有多个账号都有这个模型时才提示 `服务商/模型`。
- 已不存在的旧名字标黄，移除后才能保存；输入框里留着没选中的文字也不能保存，否则会被当成“不限”。
- `client.set_policy` 拒收不存在的名字和通配符，界面之外也存不进去。之前文案写过的 `loadout/*` 前缀一并取消，范围要放宽用账号范围。

## 第三轮验收反馈（2026-11-03）

用户意见：中间图标太扁平；动效单一；希望点击聚焦一条流向、拖动调整上下游顺序；配色单一，先做几份预设配色看提升多少，不行再换整体风格。这一轮只改前端。

- 图标：`HubMark` 改成三层立体叠板，放在有明暗的圆盘上；有流量时叠板微微张开，图标跟着配色走。
- 配色：六套预设（松石、青花、紫藤、琥珀、胭脂、水墨），各有浅色和深色。令牌写在 `[data-palette]` 上，所以预览卡片能用自己的颜色画出来。入口在左下角调色板图标和设置页，保存在窗口本地。
- 动效：每个节点有自己的颜色，光点的颜色在中枢处过渡。线束本身流动，速度跟实际字节速度走，并且渐入渐出。光点随机到达，大小和速度不一，带轻微摆动，进中枢有短暂停留，落地有涟漪。请求发出时有一个灰点走向上游。中枢随流量发亮再慢慢冷却。没有请求时动画循环完全停止。
- 聚焦：点击一端，其他线变淡，对面只亮真正来自它的比例，数字换成这条流向的量；点空白处或按 Esc 退出。
- 拖动：拖动一端调整顺序，线束平滑过渡；顺序存在窗口本地，和故障切换顺序无关；标题旁的小箭头恢复默认；Alt+上下键也能移动。
- 节点不再因用量变化自动换位：首次出现时按大小排，之后行位不变，切换指标或时间段时才重排。

走查时修的问题：`.flow-canvas svg` 的规则把图内所有图标也撑满了画布；快速松手时最后一次移动还没渲染就提交，节点少走一格。

## 第四轮验收反馈（2026-11-03）

用户意见：点击用量柱状图进入当日简报，用带动效的环状图；加一个按月分块的热力图，参考 Codex 个人页；用量和其他页面也要有总览那样的切换动效；全局动效加开关，规避性能开销。

- 当日简报：点柱子、热力图方块或总览上的小柱子打开（`#/stats/YYYY-MM-DD`）。右侧抽屉，不挡图表，开着时可以直接点别的日子，左右方向键换天，Esc 或点别处关闭。内容是请求数、成功率、费用，Token 按模型、账号、客户端的环状占比，各小时的忙闲。
- 热力图：最近 12 个月，每月一块，每天一格，点击打开简报。视图分每天、每周、累计；顶部是累计 Token、单日峰值、最长和当前连续天数。
- 页面动效：页面分段进场，左侧导航有一块滑动的标记，数字滚动，柱子生长，占比条展开，只有新来的行做进场动画。
- 动效开关：设置页和调色板菜单里都有。关掉后 CSS 动画和过渡全部停止，流向图的动画循环不再启动，数字直接显示结果。系统关闭动画效果时同样处理。

后端两处必须跟着改：

- 统计原来按 UTC 分天。这台电脑的时区现在是 UTC+11，所以上午 11 点前的请求会算到前一天。`stats.summary` 现在接收 `tz_offset_min` 和 `until_ms`，按查看者的本地日期和小时分组。
- 请求记录上游默认只留 7 天，热力图和“最近 90/365 天”都没有意义。supervisor 现在设 `CALL_LOG_RETENTION_DAYS=400`、`CALL_LOGS_TABLE_MAX_ROWS=1000000`，设置页显示实际生效的天数。已经被删掉的记录找不回，正式版 v0.4 的统计也不导入，所以热力图从现有数据开始。

查到的问题：

- 上游有第三条删除路径。`cleanupCallLogs`（每 6 小时）只读 `retention.callLogs`（默认 30 天），不看环境变量，所以只设变量的话 30 天前的记录还是会被删。回归里加了断言：未修补时报 “a 100-day-old request was deleted”；`src/lib/db/cleanup.ts` 改成环境变量优先后通过。断言同时要求 500 天前的记录被删，证明这次清理确实跑过。
- 动画的 `forwards`/`both` 填充会让元素一直按 `will-change: transform` 处理，弹窗这种 `position: fixed` 的子元素会被困在里面，所以全部用 `backwards`。
- 弹窗和简报是 `.page` 的直接子元素，一开始也吃到了页面进场动画，打开时会慢半拍并下移 8px；已排除。
- 一年 365 格各自做动画会产生几百个图层，改成每月一块进场。趋势图超过 60 根柱子时不做单根生长。日志表最多 1000 行，只有前 14 行做进场动画。

## Decisions
- 复用原版页面而不是重写：用户最在意的正是这些功能，重写只会再丢一次。
- 写操作走原生 REST：少维护，且不绕过 vault 与校验。例外是客户端每分钟上限：原生路由的 schema 不收这个字段，经 `updateApiKeyPermissions` 写入。
- 登录不是删除鉴权，而是把凭据交给桌面壳：`/api/*` 暴露在 loopback 上，无鉴权会让其他本机用户可管理。
- 指定账号是偏好，子号池是硬范围：与 ADR-003 §8 保持一致，见[记录](../../research/2026-11-02-fusion-product-rebuild.md)。
