# ExecPlan 052 — 实际旧池映射与完整组合升级

## Goal
补齐实际旧账号池的显式迁移映射，并重新验证包含050全部适配的跨版本升级与回滚。仅保留一个最终当前候选包。

## Context
用户授权只读核对正式配置元数据、在隔离实例验证，不做UI、客户端调试、正式切换或提交上传。2026-10-31官方Release列表最新仍为v3.8.52，因此使用已发布v3.8.51→v3.8.52完整组合重验，不把未发布main或未来版本当正式升级成功。

## Existing behavior
050最终包已通过120项隔离检查，051已清理包与缓存，当前v52源码和开发依赖保留。旧池codex-sub/CommandCode/OpenCode与WorkBuddy成员曾缺绑定；编译器保留不支持策略的显式拒绝。备份恢复严格匹配发行ID。

## Constraints
只读正式SQLite路由元数据，不读取正式凭据、不调用真实Provider。账号标识输出为逻辑ref，不落真实ID/邮箱。外部401/429/真实轮换单列。只用mock和loadout-test凭据命名空间。保留所有既有未提交源码。

## Architecture impact
复用原生SQLite、路由和协议。只修实际映射所需的有限工具缺口；无可用Transport的成员不能伪装为可上线，不静默删成员或接入第二套正式Loadout网关。旧版仅临时升级基线，最后清理。

## Files expected to change
fusion的必要映射/升级工具；development/experiments/omniroute-phase12的定向验收和证据；临时旧版源码；当前上游适配仅在真实反例需要时改动；ADR、来源记录与报告。

## Implementation stages
1. 只读当前池元数据，列出成员到目标接入/模型/账号范围与阻塞。
2. 准备包含全部当前适配的v51基线，顺序构建旧基线和当前v52，不复制开发依赖。
3. 通过旧版正常管理建立映射和合成凭据，备份；新版本实际打开旧DB、执行原生migration，验证规则、凭据、节流和窄连接器。
4. 匹配旧程序和升级前状态执行真实隔离回滚，最终对v52包集中回归。
5. 清理旧包、临时worktree与构建缓存，仅留一个当前候选包和精简证据。

## Tests
实际元数据对应的完整成员/顺序/模型映射；三协议不越界与故障转移；不支持接入显式阻塞；凭据更新删除导出恢复；有界等待、429节流；真实SQLite版本变化和恢复；WorkBuddy首行/工具/轮换mock；同包回归与清理。

## Performance validation
复用已有本地HTTP mock基准和节流真实时间间隔，不重跑Rust基准或宣称模型性能。

## Security considerations
不向普通文件写真实secret；只读源不更新正式数据。测试秘密随机生成，精确服务名前缀清理。出站只loopback。元数据与适配通过不等于真实账号可用。

## Migration considerations
未确认的成员保留完整映射条目与激活阻塞；不强行换模型/替代账号。升级/回滚均用独立实例，不能用旧程序打开已升级DB。跨版本导入需明确允许的来源/目标版本，不能取消原有备份版本检查。

## Known risks
目前没有后续正式v53，故本轮不能覆盖未来升级。v51工具链可能需按锁文件恢复依赖；复用缓存不等于洁净安装。当前真实池可能包含超出API-key安全profile的订阅成员，需明确保留而不是扩大认证适配。

## Definition of done
每个实际池成员都有接入映射或明确阻塞；完整组合升级/回滚有实跑证据和维护差异统计；最终包回归通过或具体失败保留；一个当前候选包，正式环境不变。
